# 更新の確認と入れ直し

更新の確認は、新しいバージョンが出ているかを[Releases](https://github.com/limit7412/VRCARKitBlendShapeGenerator/releases/latest)へ問い合わせる仕組みである。
問い合わせはエディタの読み込み時に自動で走るため、インスペクタを開く必要はない。

エディタから外部へ通信するが、送るのはリリース情報の取得要求だけで、1日1回までである。
通信を望まない場合は Preferences > ARKit BlendShape Generator から止められる。
止めれば問い合わせを行わず、更新の通知も出ない。

知らせるのは安定版が出たときだけである。
プレリリース（`0.1.10-test4` など）を入れている場合も、同じバージョンの安定版が出た時点で更新として扱う。

## インストール方法による扱いの違い

更新の手段はインストール方法で違うため、扱いもそれに合わせて変わる。

`Packages/` 配下（VCC/ALCOM経由）の場合は、新しいバージョンが出ていることをインスペクタで知らせるだけにとどめる。
バージョンはVCC/ALCOMが `vpm-manifest.json` で管理しているため、こちらでファイルを置き換えると管理側の記録と実態がずれる。

`Assets/` 配下（unitypackageから導入）の場合は、そのまま更新できる。
新しいバージョンを見つけると、そのバージョンについて一度だけダイアログで知らせる。
そこで「あとで」を選んだ場合は、インスペクタの先頭に出る「更新する」ボタンからいつでも実行できる。

## 更新の仕組み

更新は、Releasesからbooth用zipを取得し、GitHubが示すダイジェスト（sha256）と照合してから取り込む。
取り込みの前に、新しいバージョンに無くなったファイルを削除し、更新前のフォルダを `Temp/` へ控える。
取り込みは取り消せないため、実行前に確認を挟む。
フォルダの中を自分で書き換えている場合は、先に控えを取ること。

フォルダを `Assets/AtelierKairox/VRCARKitBlendShapeGenerator/` から動かしている場合、この更新は行えない。
取り込み先はunitypackageの側で決まっており、手元の位置へは追従しないため、実行すると同じアセンブリがプロジェクトに二組できてしまう。
この場合は次の「手で入れ直す」の手順で更新する。

## 手で入れ直す

手で入れ直す場合は、`Assets/AtelierKairox/VRCARKitBlendShapeGenerator/` をフォルダごと削除してから、新しいunitypackageを取り込む。
unitypackageの取り込みはファイルの追加と上書きだけを行うため、上書きするだけでは、そのバージョンで削除されたファイルが残る。

アバターに追加済みのコンポーネントは、削除して入れ直しても失われない。
配布物のGUIDをリポジトリで固定しており、バージョンが変わっても参照が切れないようにしている。
